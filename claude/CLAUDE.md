# Claude Code 固有

- モデル割当: 最上位モデル(Fable 等)は設計・レビュー・意思決定。サブエージェントへの委譲時は難易度でモデルを明示指定する — 機械的な読取・収集・定型変換=haiku / 実装・調査の標準=sonnet(既定) / 高難度実装・検証がクリティカル=opus。迷ったら一段上(下位モデルの失敗はやり直しで高くつく)。
- PR 作成は create-pr Skill、Codex 連携(振り分け・裏取りループ・書込委譲)は codex Skill に従う。
- 意味検索: 名前でなく振る舞いで探すとき(「〜しているのはどこ？」)は、Read の前に意味判定 CLI の Skill で読む場所を絞る。コードを関数単位(シグネチャ+本体の先頭)に切り出して判定し、確率の高い上位だけを Read する。1段目は速いモデルで広く、150 件以下に絞ったら精度の高いモデルで判定する。1行単位では判定しない(確率に差が出ない)。判定サーバーに届かなければ従来の手順で探す。
- 成果物サニタイズ: Plan モードの最終プラン提示、および既存資料(Confluence・Artifact・仕様書等)の更新時は、依頼がなくても sanitize-artifacts Skill の原則を適用する。最終設計を最初から計画したものとして書き、会話の経緯を知らない読者に通じない文を残さない。
- メモリ衛生(システムプロンプトのメモリ規則への追加分): 本文を更新したら frontmatter description と MEMORY.md 索引行も同時に更新する(乖離が最頻の腐敗モード)。前提が覆ったら削除でなく旧記述に訂正を追記して相互リンク。チケット完了・PR マージを見届けたら追跡メモに完了を明記。メモリが参照する申し送り・設計原本は `~/.claude/handover/` に置く(plans/ の .md は 30 日で自動削除)。
- 定期棚卸しの実施機構: SessionStart hook(tanaoroshi-reminder.sh)が `~/.claude/.last-tanaoroshi` の 30 日超過で注意喚起。Skill 候補・オープンループは SessionEnd hook(collect-session.sh)が collect-queue.md へ自動収集し、採用判断は棚卸しで K が行う。
