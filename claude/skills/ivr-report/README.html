IVR ログレポート 使い方

IVRのコールログ CSV から、電話番号登録率のレポートを作るツールです。 CSV を渡して実行すると、下の 3 つが出ます（欲しいものだけ選べます）。

必要なもの: Python 3.9 以上だけ。 Mac に最初から入っている Python で動くので、インストールは何も要りません （ターミナルで python3 -V と打つと確認できます）。

出てくるもの

出力中身使いどころ
HTML 全体／平日／休日のタブ切替、グラフ付きの 1 ファイル 共有・報告。そのままブラウザで開ける
Markdown 同じ数字のテキスト版 Slack・Confluence・チケットに貼る
CSV 離脱者（登録に至らなかった着信）の一覧 折り返し架電の検討

ログ CSV は input_logs/ に置くと分かりやすく、出力は output/ の下に実行した日時のフォルダができて、その中に入ります （例: output/20260827-181903/）。前に作ったレポートを上書きしないので、 条件を変えて何度も試して見比べられます。

1使い方（Claude Code から・おすすめ）

同梱の Skill を入れると、「IVR のレポート作って」と言うだけで済みます。

入れる（初回だけ）

このフォルダごと丸ごとコピーします。

使う

Claude Code に話しかけます。

話しかけかたの例

IVR のレポートを作って。ログは ~/Downloads/report.csv

形式（HTML / Markdown / CSV）はその場で聞かれるので、選んでください。 期間を絞りたい、テスト番号を除きたい、といった要望もそのまま伝えれば通じます。

2使い方（ターミナルから直接）

このフォルダに移動して実行します。

output/<実行日時>/ に 3 種類のファイルが出ます。実行すると 作られた場所が表示されます。まず試すなら同梱のサンプルで。

3レポートの読み方

登録率

登録とは、IVR のステップ "1-7"（電話番号通知）の webhook が 200 / result=OK で完了したこと、つまり顧客情報が CRM に渡ったことです。

登録率 ＝ 登録数 ÷ 受電数。0 秒で切れた着信（IVR が応答する前の切断）を分母から 外した「0秒除外」の値も併記しています。どちらを見るかは用途しだいですが、 全着信ベースを主指標、0秒除外を補助として扱ってください。

経路 A と経路 B

同じ IVR への着信でも、発信元番号に何が乗ってくるかが 2 通りあります。 これがレポート全体で一番大事な区別です。

A: 親番号媒体

CTI（CT-e1）を経由して転送

発信元番号
0120 / 0800 の媒体のフリーダイヤル
誰からの電話か
分からない。番号が媒体のものに置き換わる
折り返し架電はできない

B: 子番号直着信

IVR へ直接着信

発信元番号
顧客本人の番号がそのまま乗る
誰からの電話か
ほぼ本人と分かる
折り返し架電に使える

そのため、

  • 人数（何人が電話してきたか）が数えられるのは B 経路だけです。 レポートの「B: 子番号直着信の人物登録率」がその主指標です。
  • A 経路の人数は原理的に不明なので、全体のユニーク登録率は 「◯◯〜◯◯%」のレンジ推定として参考値で出しています。
  • B 経路の受電が極端に少ないときは、人数系の指標を「算出対象外」と表示します。

離脱者 CSV

離脱＝ 登録に至らなかった着信すべてです。IVR で「3」を押して自分から終了した ものも含みます（CRM には何も残らないため）。

CSV の 折り返し架電 列を見てください。

  • 可 … 経路 B。発信元がほぼ本人番号なので、そのまま架電先に使えます。
  • 不可（媒体FD） … 経路 A。番号は載っていますが媒体のフリーダイヤルです。 ここに架電しても顧客には繋がりません。

最終到達ステップ は、その通話が IVR のどこまで進んだかです。 (ステップ記録なし) はどのステップも記録されなかった通話で、 通話秒数が数十秒あるものも含まれます（0 秒切断とは限りません）。

CSV は Excel でそのまま開けます（BOM 付き UTF-8）。

全体 / 平日 / 休日

HTML レポート上部のタブで切り替わります。平日・休日は着信のカレンダー日付で 判定しています（祝日は自動判定）。

日跨ぎの注意

IVR の夜間帯は日を跨ぐため、たとえば月曜 0〜8 時の着信（日曜夜シフトの後半）は 平日側に入ります。1 夜を 1 行として見たい場合は、レポート下部の 「夜間シフト単位」の表を使ってください。

異常日・欠測日

特定の日に普段と桁の違う着信があった場合、--exclude-dates でその日を指定すると、 主指標を「平常ベース」（その日を除いた値）にし、異常日の内訳を別セクションに出します。 「異常日込み」の値も併記されるので、両方を見て判断できます。

ログのエクスポートが失敗して 0 件になっている日は --missing-dates で指定します。 その日は日平均などの分母から外れ、日別表に欠測フラグが付きます。

なお --exclude-dates を使うと、レポートの離脱数（異常日を除いた平常ベース）と 離脱者 CSV の行数（異常日も架電対象として含む）がずれます。実行したときに両方の数が表示されます。

4困ったとき

メッセージ意味と対処
ヘッダ列が見つかりません IVR のコールログではないファイルです。CT-e1 の通話呼詳細などと取り違えていませんか
列の解決に失敗（候補2件） ヘッダに 1-7…電話番号通知 を含む列が複数あります。エラーに実際のヘッダが出るので相談してください
集計対象の着信がありません --start / --end がログの範囲外です。エラーにログの実際の期間が出ます
文字コードを判別できません UTF-8 でも CP932 でもない CSV です。書き出し直してください
未知の出力形式 --format に指定できるのは html / md / csv です

HTML が真っ白な場合は、ファイルをブラウザにドラッグ＆ドロップしてみてください。 HTML は外部ファイルに依存しない 1 枚もので、そのまま添付・共有できます。

5中身の構成

このフォルダはそのまま Claude Code のスキルとしても置ける構成です （SKILL.md が同居しているため）。ターミナルから直接使う場合も同じフォルダで動きます。

サンプルは動作確認用に生成した架空のデータで、実在の顧客番号は含みません。

扱えるログについて

テナントによって CSV の列構成が違うため、列は位置ではなくヘッダ名で解決して います。必要な列が見つからないときは、推測で続けずエラーで止まります。 文字コードは UTF-8 / CP932 を自動判別します。

集計できないこと

このツールが読むのは IVR のコールログだけです。次は分かりません。

  • A 経路の着信が誰からか — 発信元が媒体のフリーダイヤルに置き換わっているため。 CTI（CT-e1）側の通話呼詳細と突き合わせる必要があります。
  • どの広告・キャンペーン経由か — IVR ログには媒体のフリーダイヤルまでしか 残りません。
