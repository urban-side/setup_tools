# IVR ログレポート

IVR 事業者から書き出した IVR コールログ CSV を受け取り、レポートを生成する。

## 進め方

### 1. ログ CSV の場所を確認する

ユーザーがパスを言っていなければ聞く。よくある置き場所は
このパッケージの `input_logs/`、または `~/Downloads` の `report*.csv`。
複数月ぶんを渡された場合はまとめて指定してよい（ID で重複排除する）。

CSV が IVR コールログかどうかは、ヘッダに `着信日時` `発信元番号` `完了フラグ` と
`"1-7"…電話番号通知` を含むかで判別できる。含まなければ別物なので、
どのファイルが正しいかをユーザーに確認する。

### 2. 出力形式を聞く

**必ずユーザーに確認してから実行する。** 3 つの形式を提示し、複数選択可と伝える。

| 形式 | 中身 | 向いている用途 |
|---|---|---|
| **HTML** | 全体／平日／休日のタブ切替、グラフ付き。単体で開ける 1 ファイル | 共有・報告。社内 HTML 共有に貼る |
| **Markdown** | 同じ数字のテキスト版 | Slack・Confluence・チケットに貼る |
| **CSV** | 離脱者一覧（登録に至らなかった着信） | 折り返し架電の検討 |

迷っている様子なら「HTML と CSV」を勧める。

### 3. 集計条件を確認する

既定ではログの全期間を集計する。以下に**心当たりがある場合だけ**聞く。深追いしない。

- 対象期間を絞るか（`--start` / `--end`）
- 異常な着信スパイクがあった日（`--exclude-dates`）— 平常ベースから除外し内訳を別掲
- ログが欠落している日（`--missing-dates`）— 日平均などの分母から除外
- テスト用の発信元番号（`--test-sources`）— 主集計から分離して別掲
- レポート見出しの副題（`--title`、例: `"拠点A（TENANT_A）"`）

### 4. 実行する

`ivr_report.py` はこの SKILL.md と同じディレクトリにある。そこへ移動して実行する。

```bash
cd <このスキルのディレクトリ>
python3 ivr_report.py <ログCSV...> --format html,csv --title "<副題>" --out ~/Desktop/ivr-report
```

`--format` はユーザーが選んだものだけを渡す（`html` / `md` / `csv` をカンマ区切り）。
`--out` の既定は同ディレクトリの `output/`。スキルとして `~/.claude/skills/` 下に
置いてある場合はユーザーが見つけにくいので、`~/Desktop` など分かる場所を指定する。
`--out` の下には実行日時のフォルダが自動で切られる（`output/20260827-181903/` のように）。
過去の実行を上書きしないので、条件を変えた再実行はそのまま繰り返してよい。

### 5. 結果を報告する

標準出力に出る受電数・登録数・登録率・離脱数をそのまま伝え、生成ファイルの
パスを示す。HTML は「ブラウザで開いてください」と添える。

数字を解釈して伝えるときは、レポート内の定義に沿うこと（下記）。**ログにない
ことを推測で補わない。** 特に、A 経路（発信元がフリーダイヤル）の着信は発信元が
本人番号ではないため、そこから人数や個人を語らない。

## 集計の定義

- **登録** = Step `"1-7"` の電話番号通知 webhook が `200 / result=OK` で完了したこと。
- **離脱** = その登録が成立しなかった着信すべて。IVR で「3」を押して自ら終了した
  ものも離脱に含む（CRM には何も残らないため）。
- **経路 A（親番号媒体）** = 発信元が `0120` / `0800`。CTI 経由で、発信元は媒体の
  フリーダイヤル。**本人番号ではないので折り返し架電に使えない。**
- **経路 B（子番号直着信）** = それ以外の発信元通知あり。顧客番号が透過するため
  ほぼ本人番号。折り返し架電に使えるのはこの経路。
- **非通知** は主集計から分離して別掲する（テスト・ボット疑いを含むため）。
- **平日／休日** は着信のカレンダー日付で判定する。IVR の夜間帯は日を跨ぐため、
  月曜 0〜8 時の着信（日曜夜シフトの後半）は平日側に入る。

## つまずいたとき

| 症状 | 対処 |
|---|---|
| `ヘッダ列が見つかりません` | IVR コールログではないファイル。CT-e1 の通話呼詳細などと取り違えていないか確認する |
| `列の解決に失敗（候補N件）` | ヘッダに `1-7…電話番号通知` を含む列が複数ある。実際のヘッダを見せて、どれが正か確認する |
| `集計対象の着信がありません` | `--start` / `--end` がログの範囲外。エラーに出るログの実期間を伝えて指定し直す |
| `文字コードを判別できません` | UTF-8 / CP932 いずれでもない。書き出し直しを依頼する |

## やらないこと

- 顧客の電話番号を会話やチャットに貼り出さない。CSV のパスを渡すに留める。
- レポートを外部サービスへアップロードしない。共有先はユーザーが決める。
